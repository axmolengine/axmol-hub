Keep the first pass narrow. All paths below are relative to the matched engine root (prefix `axmol/` inside an embedded game). Once those four sources and the local Sprite setup agree, give the patch and verification steps rather than auditing unrelated rendering APIs.

1. Start with `<core>/2d/Sprite.h`: find the program-state overload. In the same tree, read the matching `loadProgram` declaration (`core/renderer/backend/ProgramManager.h` in the 2.x reference; `axmol/renderer/ProgramManager.h` in the 3.x reference). Check the vertex layout, state type and ownership rather than translating old GL calls.
2. In `tests/cpp-tests/Source/ShaderTest/ShaderTest.cpp`, read just `SpriteBlur::initProgram` and its draw/update code. Follow the actual vertex name, fragment resource key, uniforms, texture dimensions, and retain/release pattern. Select the Sprite in the game's own scene, not the test harness.
3. Trace that resource key to a shader **source** and the CMake rule that compiles it. The reference trees both load `custom/example_Blur_fs`, but 2.x's `tests/cpp-tests/Source/shaders/example_Blur.fsh` and 3.x's `tests/cpp-tests/Source/Shaders/example_Blur_fs.hlsl` are different inputs. Find `app_shaders_dir` in `cmake/Modules/AXBuildHelpers.cmake`; use the exact directory case, suffix and generated resource name in this game. Inspect the compiler rule only if those do not line up.
4. Cite this version's `file:line` for the declaration, the example and the build rule. In Agent mode, if asked to implement, make the smallest game-only change: one shader and one Sprite setup, with nonzero blur radius and sample count. Do not edit the engine or copy an entire test scene.

**Verify:** from the temporary game, run the matching engine's `axmol build` for the host (e.g. `axmol build -p osx -a arm64` on an Apple Silicon Mac). Reconfigure if an added shader wasn't discovered. Check the compiler exit and the custom shader in the packaged resources, not just the C++ compilation. Launch the game with the same engine/target and compare the textured sprite's edges with the effect disabled. In Plan mode describe these steps, don't execute them.
